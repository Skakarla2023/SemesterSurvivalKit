# Characterstics of SRS

## 1. Correctness

- Provide accurate functional and non-functional requirements as discussed with the client.

## 2. Completeness

- Should complete all essential features like functionality, design, and verifiability.

## 3. Consistency

- Same abbreviation, tabular format. Formats should be same everywhere.

## 4. Unambiguousness

- Should be clear to understand without any confusion.

## 5. Ranking of importance and stability

- Every requirement in SRS is important, but it is important to identify the tasks that are urgent so that they are not left behind.

## 6. Modifiability

- Developers should be able to modify any feature without affecting others.

## 7. Tracibility

- Each requirement should have a numeric value so that it is easy to identify them.

## 8. Verifiability

- Testers and stakeholders should be able to verify it correctly.

## 9. Testability

- An SRS should be written in such a way that test cases can ne easily written from them.

## 10. Design independence

- At the end there should be multiplt implementations of the system, and we should select one from them, instead of a single implementation.

## 11. Understandable by the user

- Each aspect should be clear and simple.

## 12. Correct level of abstraction

- When you write SRS in the requirement stage, it must be very detailed and clear.
- Because developers,clients and testers should all understand what we built.
