# SRS

- Software Requirement specification is a document that outlines the functional and non-functional requirements for software development.
  
- The need for SRS is critical in software development for several reasons:

1. Clear understanding of the system
2. Foundation for design and development
3. Reference for testing
4. Scope and schedule management
5. Mitigates Risks
6. Facilitates communication between stakeholders
7. provides basis for management and updation of resources
8. Legal Agreement

## Clear understanding of the system

- It explains what the software **should do** and what it **should not do**.
- This avoids confusion between clients, developers and stakeholders.
- For eg if a client wants a login page with email and dob, and these are specified in the **SRS**, so the developer do not create a login page using only username.

## Foundation for design and development

- Once requirements are made clear, the SRS works as a blueprint for the software development.
- Without that, the design would just be random or it may not match the actual needs.
- eg: an architect needs a building plan before construction, in the same way developers need **SRS** as it provides a foundation for development.

## Reference for testing

- Testers check whether all the requirements specified in the SRS are satisfied.
- Each requirement in the SRS acts as a testcase.
- For eg: if SRS says, the system should allow the users to reset their password, the developers test whether such feature exists in the software or not.

## Scope and schedule management

- SRS defines the scope(what is included and what is to be excluded).
- It helps in seting realistic schedules.
- eg: if any feature is to be added, it sets realtime goal, the project timeline will include a realtime milestone.
